# Sync Ledger

Working memory for the sync-upstream skill. Record only what changes how a sync is performed: standing decisions, watchpoint triggers, and the full-audit marker. Never record what the code or git history already shows, and never grow this into a fork feature list.

Self-cleaning rules (apply during every sync's ledger update):

- Remove a watchpoint after two consecutive syncs in which its path was untouched by upstream or merged trivially.
- Remove a standing decision when the code it governs no longer exists on `dev`, or upstream ships the change named in its revisit condition (then re-decide with the user).
- Update the audit marker after every full audit or explicit postponement.

## Standing decisions

- **Claude skill picker — keep both layers** (2026-07-24). Fork's `listSkillsForCwd`/`adapter.listSkills` (SDK `reload_skills`, per-thread cwd) is the primary source; upstream's `discoverClaudeSkills` provider-status scan is the fallback. Upstream's scan receives the server's own `ServerConfig.cwd`, so dropping the fork path would lose project-scoped skills. Revisit only if upstream makes discovery per-thread-cwd.
- **Provider command flow — keep steering and title-pin guards** (2026-07-24). Fork's failed-steer handling preserves the running session and active turn, while ordinary startup failures still use upstream's error transition. `titlePinned` protects explicit CLI titles before and after asynchronous title generation. Both remain compatible with upstream interrupt/title generation. Revisit if upstream distinguishes failed steers itself or persists an equivalent explicit-title pin.
- **Repository identity — deliberate hybrid, do not deduplicate** (2026-07-24). Fork persists identity (migration 035 + write-time enrichment in `OrchestrationEngine.ts`); upstream resolves at query time, and the merged `ProjectionSnapshotQuery.ts` writes resolved values back into the fork's column as a cache with stored-value fallback. Both paths cover cases the other cannot.
- **Event replay bounds — complementary, not duplication** (2026-07-24, updated 2026-07-29). Upstream's `SHELL_RESUME_MAX_GAP` bounds shell resume; fork's aggregate-filtered `readEvents` (`ws.ts` thread-detail catch-up) filters per-thread replay at the SQL level. Keep both. Upstream removed the unused public `orchestration.replayEvents` RPC on 2026-07-29; do not restore that dead RPC or its repository-identity enrichment tests.
- **Effect beta bumps expose fork-only APIs first** (2026-07-28, updated 2026-08-05). Typecheck the server immediately after an Effect beta bump and read cascades bottom-up. Beta 102→103 removed `Schema.UnknownFromJsonString`; fork provider/session-import code must use `Schema.fromJsonString(Schema.Unknown)`. Fix concrete removed APIs before diagnosing the resulting `any`/`unknown` requirement-channel cascade.
- **Beta flags resolve through a hook, never the raw setting** (2026-07-28). Upstream defaults sidebar v2 (web) and thread list v2 (mobile) ON for nightly/dev/preview builds, gated by `sidebarV2ConfiguredByUser` + `useSidebarV2Enabled()` / `useThreadListV2Enabled()`. Any fork code that branches on either flag must call the hook — reading `settings.sidebarV2Enabled` or `preferences.threadListV2Enabled` directly reads "never chosen" as "off" and ignores the build-stage default. Consequence for the fork: dev-flavor builds now start on v2 by default, so fork sidebar work must land in `SidebarV2.tsx`, not only `Sidebar.tsx`.
- **Project-actions dialog footer — fork and upstream buttons coexist** (2026-07-28). `SidebarV2.tsx` footer keeps the fork's `mr-auto` "Archived threads" button leftmost, then upstream's single-member "Remove project", then "Close". Upstream's conditional `sm:justify-between` was dropped as redundant under `mr-auto`. Revisit if upstream restructures that footer again.
- **Sidebar v2 indicators and thread actions coexist** (2026-07-30). Keep upstream's terminal status, title-regeneration state, and Copy path/Copy branch alongside the fork's provider icon/compact metadata and Fork/Archive actions. When their adjacent edits conflict, retain the fork's row layout and insert upstream status into its shared metadata/accessibility slots so slim, compact, and expanded rows all remain covered. Revisit if upstream ships equivalent fork/archive actions or replaces the row/action model.
- **Environment identification keeps two independent gates** (2026-07-29). `resolveSidebarStageBackdropVariant` takes an options object: `enabled` implements upstream's artwork/pill/none setting, while `isDevelopmentBuild` preserves the fork rule that Dev artwork never appears in packaged builds. Nightly artwork remains eligible in packaged builds. Do not collapse these back into one positional boolean.
- **Mobile v2 rows keep fork filters around upstream lifecycle sections** (2026-07-29, updated 2026-08-05). Upstream's shared `buildThreadListV2ListItems` owns active → pending → settled ordering, pending-row metadata, the snoozed shelf, and section-divider suppression. Before that splice, both `HomeScreen.tsx` and `ThreadNavigationSidebar.tsx` must retain the fork's environment, model, project, attention, and search predicates while also passing upstream's `matchedThreadKeys` and rendering message-match excerpts. Rows must keep `resolveThreadProviderDriver` and project accents while adopting upstream lifecycle actions and `showTrailingDivider`; preserve both the accent overlay and divider gate when their row wrappers conflict. Mobile grouping mode now resolves through `state/project-grouping.ts`, while the fork's visibility filters remain a separate `HomeListOptionsProvider` concern.
- **Fork requirements override upstream AGENTS defaults** (2026-07-29). Keep upstream's broad project guidance in `AGENTS.md`, but retain the leading private-fork requirements for full local gates, `dev`/mirror-only `main` topology, focused fork testing, private build helpers, and controlled-browser verification of shared URLs. These explicitly override conflicting upstream defaults such as CI-only repo-wide checks or rebasing feature work onto mirror `main`.
- **test-t3-mobile skill carries fork hardening** (2026-07-29). `.agents/skills/test-t3-mobile/SKILL.md` deliberately diverges from upstream #4165: resolved (not hardcoded) bundle identifier and workspace names, native-compatibility precheck, per-worktree derived-data pinning, physical-device section, opt-in trigger clause in the description, and expanded troubleshooting; `references/local-setup.md` is fork-only and must never go upstream. On sync conflicts, take upstream's structural changes but preserve these additions; never revert to upstream's hardcoded `com.t3tools.t3code.dev` / `T3CodeDev.xcworkspace` constants. Revisit if upstream ships its own identity-resolution step.
- **Migration numbering** (2026-07-24, updated 2026-08-07). Fork history occupies 033–043; upstream pinning is `044_ProjectionThreadsPinned` and upstream's turns keyset index (their 037) landed as `045_ProjectionTurnsKeysetIndex` on `dev`. Never renumber shipped fork migrations. Renumber each new upstream migration after the highest `dev` ID (currently 045) and verify ordering whenever upstream adds one. Pure-upstream databases with overlapping numeric IDs are not interchangeable with fork databases because the migrator tracks only the latest numeric ID.
- **RPC authorization stays centralized and exhaustive** (2026-07-29). Use upstream's typed `apps/server/src/auth/RpcAuthorization.ts` map and never restore the old local map in `ws.ts`. Fork RPC scopes remain `serverListProviderSkills` → orchestration read, `sessionImportListCandidates` → orchestration read, and `sessionImportImport` → orchestration operate. Revisit if those methods are removed or replaced.
- **Fork README replaces upstream's intro; never merge upstream prose in** (2026-07-30). `README.md` is the only file `main` and `dev` intentionally differ on, so every upstream edit to the opening description conflicts. Always keep the fork's "personal fork of pingdotgg/t3code" paragraph and discard upstream's replacement text — this is a mechanical `ours` resolution for the intro block only, not for the rest of the file.
- **Saved-environment action row hosts both update and edit actions** (2026-07-30). In `ConnectionsSettings.tsx`'s `SavedBackendListRow`, upstream moved `ServerUpdateAction` out of the version-drift paragraph into the trailing action row — the same row the fork extends with its bearer-only "Edit" button. Keep both, upstream's update action first. Revisit if upstream adds its own edit affordance there.
- **Hermes follows shared provider background policy** (2026-07-29). `HermesDriverEnv` includes `BackgroundPolicy`, and Hermes leaves `makeManagedServerProvider.refreshInterval` unset so the same server setting, demand gate, and battery policy used by built-in providers controls its health refresh. Revisit if upstream changes the managed-provider scheduling contract again.
- **Thread outbox manager remains shared across web and mobile** (2026-07-30). Upstream's optimistic mobile enqueue was ported from `apps/mobile/src/state/thread-outbox-manager.ts` into the fork's `packages/client-runtime/src/state/threadOutboxManager.ts`. Both client drains must await `confirmQueued` before delivery; mobile keeps its queued-message intent/filter behavior, and web must not deliver a row whose durable write rolls back. Revisit if upstream moves the manager into shared client-runtime or changes enqueue durability again.
- **Indefinite snooze extends the shared timed presets** (2026-07-31, updated 2026-08-06). `Sidebar.snooze.ts` wraps the shared timed-preset helper to add capability-gated `until-woken` with a null wake time and timestamp-format-aware labels; compact wake labels use the shared client-runtime helper directly. Revisit if the shared preset helper supports indefinite snooze without weakening its mobile string-wake-time contract.
- **Settings search includes fork-only surfaces** (2026-08-01). Keep `/settings/extras` in `SettingsPath`, navigation labels/icons, and the searchable catalog with anchors for every Extras section. The archive search target belongs on the fork's filtered logical-project groups rather than restoring upstream's physical-project rendering. Revisit if upstream provides an extension registry for settings routes and search entries.
- **Pin and move-to-top coexist** (2026-08-05). Upstream's persistent `pinnedAt` section stays creation-ordered; fork `movedToTopAt` only reorders unpinned active threads. Hide Move to top on pinned rows. Pin promotion must unsnooze when either `snoozedUntil` or `snoozedAt` is set so indefinite snoozes wake too. Preserve both command/event/capability/projection/reducer contracts. Revisit if upstream adds transient active ordering or changes pin lifecycle semantics.
- **Upstream owns trial migration rollback** (2026-08-05). Protocol 2 backs up and restores the database, so trial startup runs migrations unconditionally. Do not restore persistence `setup(trial)`, trial options, migration-manifest preflight, or a persistence dependency on `resolveServiceLauncherMode`. Keep `PRAGMA busy_timeout = 5000` on the normal connection, voice middleware, native 128 MiB Bun/Node WebSocket limits, and all fork CLI commands.
- **Project CLI requires the live server** (2026-08-05). Do not restore writable or read-only local SQLite fallbacks for project commands. Listings and mutations fail clearly when the selected server is unavailable; the strict read-only persistence layer, schema-ledger guard, and fallback tests remain deleted. Revisit only if an offline CLI mode is deliberately redesigned with an explicit consistency contract.

- **Custom-scheme privileges are upstream's, with no fork delta** (2026-08-04). The fork's top-of-`main.ts` `registerSchemesAsPrivileged` (added by the ElevenLabs commit `58ce8ac8f` so `getUserMedia` sees `t3code://app` as a secure context) was deleted in favor of upstream's `ElectronProtocol.registerDesktopSchemePrivilegesSync()` via `DesktopPreReadyPlatform.layer`. `standard`+`secure` still cover mic capture. Upstream omits the fork's old `stream: true`, which was verified inert: recording uses `blob:` URLs and the TTS player resolves its src against `preparedConnection.httpBaseUrl`, so no media element ever loads over the scheme. If voice playback ever regresses, re-add `stream: true` to both entries rather than restoring the `main.ts` block.
- **Pre-ready startup must see the packaged-Dev flavor** (2026-08-04). Upstream's `DesktopEarlyElectronStartup` derives Linux WM class and the early settings path from `VITE_DEV_SERVER_URL` alone, which would send a packaged Dev build to `t3code` and `~/.t3/userdata`. `apps/desktop/src/app/DesktopBuildFlavor.ts` holds the shared `__T3CODE_BUILD_DESKTOP_FLAVOR__` read; `DesktopPreReadyPlatform` passes `isPackagedDevBuild` into the early resolver, and `resolveDesktopStateDir` branches to `dev-packaged` ahead of the `T3CODE_HOME` check. Any new pre-ready code that needs dev identity must use this, never raw `isDevelopment`. Revisit if upstream parameterizes early startup by identity itself.
- **Linux URL handler derives identity from `usesDevelopmentIdentity`** (2026-08-03). `DesktopLinuxUrlHandler.ts` must pass `environment.usesDevelopmentIdentity` (not `isDevelopment`) to `getDesktopScheme` and write an identity-suffixed entry name (`t3code-dev-url-handler.desktop` for dev identity), matching every other fork scheme-derivation site, so a packaged Dev build claims the dev scheme without clobbering the production handler entry. Revisit if upstream parameterizes the handler by identity or entry name itself.

- **Background liveness is presentation-only; lifecycle unblocked** (2026-08-06). Upstream's `backgroundLiveness` (Working/Monitoring) deliberately does not block settling, snoozing, archiving, cache persistence, or prewarm, and does not extend the reaper's pending-work lease — the fork adopted upstream semantics as shipped. Deferred candidate follow-ups (decide separately, not during a sync): lifecycle blocking while live, reaper counting liveness as bounded pending work, provider-instance provenance in persisted task activities, mobile Working/Monitoring parity.
- **Shell resume across restarts sends a snapshot** (2026-08-06). `ws.ts` captures `shellSequenceAtProcessStart`; a `subscribeShell` resume cursor from before this process falls back to a fresh snapshot because `backgroundLiveness` is volatile and no durable event corrects it. Keep this guard whenever upstream reshapes shell subscription/resume.
- **Liveness clearing is generation-guarded** (2026-08-06). `ProviderRuntimeIngestion` clears thread background liveness on `session.exited` only when the event's `sessionGenerationId` doesn't belong to a replaced generation, mirroring `mirrorSessionCwdOntoThread`. Do not revert to upstream's unconditional clear.
- **Subagent snapshots never advance the parent resume cursor** (2026-08-06). In `ClaudeAdapter.handleAssistantMessage`, a `parent_tool_use_id` assistant snapshot refines the owning task's model and returns; upstream's cursor update was dropped because sidechain UUIDs break cold resume. The pinned fork test guards this.
- **Workflow-script roots derive from configured Claude homes** (2026-08-06). `readWorkflowScript` accepts server-derived `permittedRoots`; `ws.ts` computes them from every `claudeAgent` instance's config dir (shadow homes resolve to the shared root via the `projects` symlink) plus `~/.claude/projects`. Never revert to the hardcoded home-dir root, and never accept client-supplied roots.
- **Background Stop state is thread-keyed** (2026-08-06). `ChatView.tsx` uses `stoppingBackgroundThreadKey` (matching `unsettlingThreadKey`), not upstream's component-wide boolean with reset-on-switch. Preserve on future ChatView merges.

- **Thread pagination is a hybrid; legacy bridge is temporary** (2026-08-07). Upstream's turn-window protocol (`turnLimit`/`beforeCursor` cursor, snapshot `page`, `threadSequence` watermark, `threadSnapshotPagination` capability) is authoritative for capable clients; the fork's client state machine, event coalescing, warm-refresh/revert/teardown hardening, message artifacts, and mobile auto underfill + top-scroll paging are preserved on top. A thread-detail response carries EITHER `page` OR the legacy `messageWindow`, never both — `projectThreadDetailSnapshot` early-returns on `page` so a turn page is never sliced again, and `makeSubscribeInput` emits `turnLimit` XOR `messageLimit`. The legacy `messageLimit` + `GET /threads/:id/messages` bridge exists only for already-deployed mobile builds: remove it after one shipped mobile release. Web/desktop stay full-history (`messageWindowLimit: null`, no `turnLimit`; the server window is opt-in per request). The mobile 750-message resident ceiling is separate local state that gates automatic refills only — never write it into `page.hasMore` and never trim inside a returned page while keeping its cursor. Prewarm still fetches unwindowed snapshots pending the PR #123 rebase.
- **Thread-detail event list is one shared constant** (2026-08-07). `apps/server/src/orchestration/threadDetailEvents.ts` exports `THREAD_DETAIL_EVENT_TYPES` (including the fork-only `thread.history-imported`) and `isThreadDetailEvent`; both the `ws.ts` replay predicate and the `threadSequence` watermark SQL must consume it. Never let upstream's inline event list reappear — an omitted fork event would make imported history look already-current.
- **Woke acknowledgement is a superset** (2026-08-07). The fork keeps the passive mark-on-open effect (and `activeThreadLastVisitedAt` selector) in `ChatView.tsx` _in addition to_ upstream's explicit acknowledgements after send/settle/archive, deliberately rejecting upstream's sticky-woke semantics to preserve open-clears-attention and mobile parity. On future ChatView/useThreadActions merges, re-add the passive effect if upstream deletes it again.
- **Bulk snooze shows one aggregate toast** (2026-08-07). Upstream's count-based aggregate toast + aggregate Undo replaced per-thread toasts, keeping the fork's indefinite presets, null `snoozedUntil` payloads, and batch navigation exclusion. Single-thread toasts build titles via `snoozedUntilToastTitle` in `SidebarV2.tsx` — the one place enforcing that `snoozeWakeDescription` is never called with null (indefinite renders "Snoozed until you wake it").
