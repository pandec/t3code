# Sync Ledger

Working memory for the sync-upstream skill. Record only what changes how a sync is performed: standing decisions, watchpoint triggers, and the full-audit marker. Never record what the code or git history already shows, and never grow this into a fork feature list.

Self-cleaning rules (apply during every sync's ledger update):

- Remove a watchpoint after two consecutive syncs in which its path was untouched by upstream or merged trivially.
- Remove a standing decision when the code it governs no longer exists on `dev`, or upstream ships the change named in its revisit condition (then re-decide with the user).
- Update the audit marker after every full audit or explicit postponement.

Verification gotchas — apply on every sync:

- Run the suite as `env -u CLAUDE_CONFIG_DIR vp run test`. This agent session exports `CLAUDE_CONFIG_DIR=~/.claude-t3/proxy`, which makes `ClaudeHome.test.ts` and `ClaudeSessionFork.test.ts` fail with a real-looking assertion (`.claude-t3/proxy` vs `.claude`). Those failures are contamination, not regressions.
- Check conflict markers with `awk '/^(<<<<<<<|=======|>>>>>>>)/{print FILENAME":"FNR}'`, not `grep` (the shell's `grep` wrapper silently reports no match for marker patterns) — and use `FNR`, not `NR`, or multi-file output reports meaningless cumulative line numbers.
- **Never `git stash` during the merge.** It silently deletes `MERGE_HEAD`, so the next commit records one parent instead of two. Cost time on 2026-08-08. If it happens, the fix is `echo <main-sha> > .git/MERGE_HEAD; echo no-ff > .git/MERGE_MODE`, then re-stage — worktree contents survive.
- Python `str.replace()` replaces **all** occurrences. When resolving several conflicts in one file by scripted replace, anchor on unique surrounding text or the first `<<<<<<< HEAD` strip will silently open the later ones.
- Check `git status` for a modified root `package.json` before staging: a previous `t3-build`/`t3-install-desktop` run can leave the packaged-Dev artifact manifest there.
