# Sync Ledger

Working memory for the sync-upstream skill. Record only what changes how a sync is performed: standing decisions, watchpoint triggers, and the full-audit marker. Never record what the code or git history already shows, and never grow this into a fork feature list.

Self-cleaning rules (apply during every sync's ledger update):

- Remove a watchpoint after two consecutive syncs in which its path was untouched by upstream or merged trivially.
- Remove a standing decision when the code it governs no longer exists on `dev`, or upstream ships the change named in its revisit condition (then re-decide with the user).
- Update the audit marker after every full audit or explicit postponement.

## Standing decisions

- **Sync target is pinned at preflight** (2026-09-04, user decision). A sync synchronizes to the `upstream-sync/main` tip fetched in preflight and never widens to commits upstream publishes during the run; those are the next sync's range. The fourth 2026-09-04 sync chased upstream through five ranges over six hours, twice discarding a fully validated `dev` candidate at the final fetch. The `origin/dev` convergence loop remains because a normal push cannot land over a moved `origin/dev`.
- **Claude skill picker — keep both layers** (2026-07-24). Fork's `listSkillsForCwd`/`adapter.listSkills` (SDK `reload_skills`, per-thread cwd) is the primary source; upstream's `discoverClaudeSkills` provider-status scan is the fallback. Upstream's scan receives the server's own `ServerConfig.cwd`, so dropping the fork path would lose project-scoped skills. Revisit only if upstream makes discovery per-thread-cwd. **Partially fired 2026-09-02 (#8778, decision 1A):** upstream now does real per-cwd discovery for CODEX and OPENCODE via `ProviderInstance.snapshotForCwd` + registry `refreshWorkspaceSnapshot` (cache-first, claim-deduped, stale-instance-rejecting); the fork's registry `listSkillsForCwd`, `CodexAdapter.listSkills`, and `listCodexSkills` were deleted in its favor. Claude is untouched — `adapter.listSkills` remains the fork's per-thread path and this decision stands for Claude only.
- **Provider command flow — keep steering and title-pin guards** (2026-07-24). Fork's failed-steer handling preserves the running session and active turn, while ordinary startup failures still use upstream's error transition. `titlePinned` protects explicit CLI titles before and after asynchronous title generation. Both remain compatible with upstream interrupt/title generation. Revisit if upstream distinguishes failed steers itself or persists an equivalent explicit-title pin.
- **Repository identity — deliberate hybrid, do not deduplicate** (2026-07-24, reaffirmed 2026-08-11). Fork persists identity (migration 035 + write-time enrichment in `OrchestrationEngine.ts`); upstream resolves at query time, and the merged `ProjectionSnapshotQuery.ts` writes resolved values back into the fork's column as a cache with stored-value fallback. Both paths cover cases the other cannot: removing persistence reintroduces archive/project-group fragmentation when a checkout disappears. Persisted identity is read-model fallback metadata, not sufficient authority for pull-request mutations; actionable operations must verify a live checkout identity or use a healthy sibling checkout.
- **Event replay bounds — upstream's selected-thread API, fork's byte budget on top** (2026-07-24, rewritten 2026-09-04, #9726). Thread resume uses upstream's `readThreadEvents`/`getThreadReplayStats` (event-store owned, explicit `toSequenceInclusive`, `LIMIT maxEvents + 1`, `hasCreateEvent` forcing the snapshot path for a recreated ID and `replayOnMissingSnapshot` when that snapshot is gone). The fork's old global-gap gate and aggregate-filtered `readEvents` are deleted: on a busy server the gate forced a full snapshot for a quiet thread, defeating the filter. Kept on top: the 8 MiB payload budget on both thread and shell replay, `SHELL_RESUME_MAX_GAP` on the unfiltered shell path, and `ProjectionSnapshotQuery.getEventReplayStats` (shell replay's only remaining consumer). Every fork-only `OrchestrationEngineShape` stub must carry both upstream members.
