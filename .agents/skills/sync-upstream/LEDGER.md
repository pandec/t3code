# Sync Ledger

Working memory for the sync-upstream skill. Record only what changes how a sync is performed: standing decisions, watchpoint triggers, and the full-audit marker. Never record what the code or git history already shows, and never grow this into a fork feature list.

Self-cleaning rules (apply during every sync's ledger update):

- Remove a watchpoint after two consecutive syncs in which its path was untouched by upstream or merged trivially.
- Remove a standing decision when the code it governs no longer exists on `dev`, or upstream ships the change named in its revisit condition (then re-decide with the user).
- Update the audit marker after every full audit or explicit postponement.

- **Thread pagination is a hybrid; the legacy bridge is now client-only** (2026-08-07, updated 2026-08-07). Upstream's turn-window protocol (`turnLimit`/`beforeCursor` cursor, snapshot `page`, `threadSequence` watermark, `threadSnapshotPagination` capability) is authoritative; the fork's client state machine, event coalescing, warm-refresh/revert/teardown hardening, message artifacts, and mobile auto underfill + top-scroll paging are preserved on top. The **server no longer honors `messageLimit`** and `projectThreadDetailSnapshot` never slices (it only strips any inbound `messageWindow`) — that half of the bridge was retired once the phone ran a turn-window build. What remains is deliberate: the client keeps its legacy path for talking to **old servers** that don't advertise the capability, and because client and server share one contract package, the `messageLimit` fields, the `GET /threads/:id/messages` declaration, its handler, and `getThreadMessagePage` must all stay — the client _encodes_ through those schemas, so deleting them would silently stop it sending `messageLimit` and make an old server return unbounded history. Retire the rest only once every server the phone reaches runs 2026-08-07 or later. Web/desktop stay full-history (`messageWindowLimit: null`, no `turnLimit`; the server window is opt-in per request). The mobile 750-message resident ceiling is separate local state that gates automatic refills only — never write it into `page.hasMore` and never trim inside a returned page while keeping its cursor. Prewarm still fetches unwindowed snapshots pending the PR #123 rebase.
